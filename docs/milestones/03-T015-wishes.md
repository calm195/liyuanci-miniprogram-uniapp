日期：2026-10-21。关联 T015、REQ-003、004、005、008；边界验证涉及 REQ-015、018。输入为需求基线 v0.2、详细设计 v0.2、共享契约 0.1.0。本阶段承接 T009 回归与 T013 认证页面提交；按用户指令先完成本仓库业务，T014 服务与 T016/T017 审核真实联调仍待交付，不将本阶段标为整体验收通过。

## 实现与关键取舍

- 注册文字心愿页面，提供广场/我的心愿、分类/校区/本人状态筛选、空态、错误重试与游标加载。刷新及切换筛选清理旧列表，离开暂停并丢弃迟到响应；空页也按服务端 next_cursor 判断是否继续，不用缓存补位。本人接口只发送契约支持的 state/cursor，分类与校区在已加载投影中筛选；公开接口发送 category/campus/cursor。
- 使用批准的六种分类、四种校区和五种报答，默认真诚感谢、7 天；正文按 Unicode 码点计数，最多 500，空白计数但全空白拒绝；期限只接受 1–30 整数。身份标签 grade/gender 的取值尚未冻结，本次不猜测或必填，合成表单不发送身份标签。
- Pinia 管理独立合成心愿，页面未保存内容仅留内存，离开清理，不读写本地缓存。支持合成草稿保存/编辑/删除、送审、人工驳回及建议、改版重审、通过待上架、主动上架。改版清理旧审核结果并递增内容版本；待审和 ready 不能误报 published；同时上架达到 3 条时新心愿保持 ready。
- 广场只展示 published 且无隐私屏障的 public 正文；不拿 own_content 补公开列表。本人遇 privacy_review_required 同样隐藏旧正文；涉校标记按公开投影显示“未经证实”，不展示学号、姓名或学生卡。匹配/已实现/已还愿/撤回/过期等状态有独立标签，不冒充上架。
- 新增列表、创建、更新、删草稿、送审、上架 API 适配，沿用统一请求层、Idempotency-Key、expected_version；送审同时传 content_version。由于 allowed_actions 动作名未冻结，真实写入口暂不接线，避免猜测动作授权；真实模式可查询列表，合成模式只操作独立内存数据，不产生令牌、不发送 API。

## 人工验证

1. 开发配置 VITE_USE_MOCK=true，进入首页“心愿广场 / 我的心愿”；首次列表为空。
2. 写虚构心愿，检查默认 7 天与最后一项报答；空白、501 码点、0/31/小数天应拒绝保存，500 emoji、1/30 天可保存。
3. 我的心愿查看草稿并编辑、删除；送审后不能编辑，审核通过仍不进广场；主动上架后广场可见。
4. 合成人工驳回，查看原因与修改建议，编辑后重新提交审核；确认旧批准不会直接继承。
5. 连续上架 3 条，第 4 条上架提示满额并维持待上架；筛选分类/校区和本人状态，确认无结果时显示空态。
6. 全程 Network 无业务请求。真实模式需后端提供对应列表、脱敏公开投影、游标与授权动作名后验证筛选、分页、401/409/503、弱网和离开页面迟到响应；写操作接线后与 T014/T016/T017 联合验证。
